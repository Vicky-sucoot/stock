# 02 投資組合、定期定額規則與計算方式

## 1. 投資組合管理

| 操作 | 規則 |
|---|---|
| 建立 | 名稱（必填，1～20 字，不可重複）、說明、顏色標籤、預設幣別（TWD／USD／JPY）、是否納入合併總覽（預設：是） |
| 編輯 | 可改名稱、說明、顏色、是否納入總覽；預設幣別只影響新增紀錄時的預設值，不會回頭改舊資料 |
| 切換 | 首頁的投資組合列表點進單一組合；組合頁上方的分段控制可在「全部／各組合」之間快速切換 |
| 排序 | 可拖曳排序（`sort_order`） |
| 封存 | 封存後不顯示在列表中，也不再產生定期定額；資料保留，仍可選擇是否納入總覽 |
| 刪除 | 需要輸入 App 密碼確認；連帶刪除該組合的計畫與紀錄（本機資料，無法還原，畫面會明確警告） |
| 同一標的跨組合 | 允許；每個組合各自計算成本，合併總覽時才加總 |

## 2. 合併總覽的計算方式

符號：`P` 是納入總覽的投資組合；`h` 是持有部位（某組合中的某標的）；`ccy(h)` 是該標的的計價幣別；`FX[c→V]` 是把幣別 c 換算成檢視幣別 V 的匯率（V 為 TWD 或 USD）。

### 2.1 單一持有部位（原幣）

- `qty`：持有數量 = Σ 買入數量 + Σ 股利再投入數量 + Σ 分割調整 − Σ 賣出數量
- `cost_basis`：持有成本，用**移動平均成本法**計算
  - 買入：`cost_basis += 成交金額 + 手續費 + 交易稅（買方，若有）+ 其他費用`
  - 股利再投入：`cost_basis += 再投入金額`（同時記一筆股利收入，見 2.3）
  - 賣出：`avg = cost_basis / qty_before`；`cost_basis -= avg × 賣出數量`；`realized_pnl += 賣出淨額 − avg × 賣出數量`。賣出淨額 = 成交金額 − 手續費 − 證交稅 − 其他費用
  - 分割：數量乘上比例，`cost_basis` 不變
- `avg_cost = cost_basis / qty`（qty 為 0 時不顯示）
- `market_value = qty × price`。price 依序取：手動覆寫值 → 自動行情 → 最後一筆交易價（並標示「以成交價估」）
- `unrealized_pnl = market_value − cost_basis`

### 2.2 換算成檢視幣別

- 市值、未實現損益：用**目前**匯率換算：`MV_V = MV × FX_now[ccy→V]`
- 累計投入與成本：用**目前匯率重估**（預設），也可在設定中切換成「按交易日匯率」（需要每筆交易記錄當時匯率，見 04 的 `fx_rate_at_trade`）
  - 預設採目前匯率的理由：資料最少，也比較好理解。畫面上「匯率換算方式」卡片會說明這兩種口徑的差別。
- 匯率影響：如果使用者選了「按交易日匯率」，就額外顯示 `匯兌損益 = 成本(目前匯率) − 成本(交易日匯率)`

### 2.3 合併指標

| 指標 | 公式（檢視幣別 V） |
|---|---|
| 總資產 | Σ_h MV_V(h) + 現金股利未再投入的累計（可在設定中選擇是否計入，預設不計入；預設下只計算持股市值） |
| 累計投入 | Σ 買入總成本（含費用）− Σ 賣出時回收的成本（avg × 賣出量），即目前持有成本總和 + 已了結部位不計入；**另外顯示**「歷史總投入」= Σ 所有買入總成本 |
| 損益（不含股利） | Σ 未實現損益 + Σ 已實現損益 |
| 損益（含股利） | 上一列 + Σ 現金股利淨額（扣二代健保、預扣稅、匯費後） |
| 報酬率（不含股利） | 損益（不含股利）／ 歷史總投入 |
| 報酬率（含股利） | 損益（含股利）／ 歷史總投入 |
| 平均成本 | 只對**單一標的**有意義。合併總覽中，同一標的跨組合時會合併成本與數量後再計算；總覽頁不顯示「整體平均成本」，改顯示各標的的平均成本列表 |

> 報酬率採「簡單報酬率」，不是年化報酬或 IRR。可在階段 A+ 加上 XIRR（資金加權報酬）。

### 2.4 資料不足時的顯示

- 缺少某標的價格：該標的用成本計算市值並標示「⚠ 無價格」；總覽 KPI 旁顯示「n 檔使用估計值」
- 缺少匯率：該幣別所有資產不換算，KPI 顯示「部分資產無法換算」，列出缺少的幣別，並提供「手動輸入匯率」入口

## 3. 定期定額計畫規則

### 3.1 頻率

| 類型 | 設定 | 產生期數的規則 |
|---|---|---|
| 每週 | 星期幾（一～五，可多選，例如每週一與週四） | 每週該日 |
| 每月 | 每月幾號（1～31，可多選，例如 6、16、26 日） | 若當月沒有那一天（例如 31 日、2 月 29 日），**延到當月最後一個日曆日** |
| 指定日期 | 使用者列出的日期清單（可重複新增） | 只在這些日期 |

每個計畫都有開始日、結束日（可留空）、暫停狀態，以及每期金額（原幣）或每期數量（二選一）。

### 3.2 休市日與週末

1. 先算出「名義扣款日」（套用月底規則）。
2. 如果名義扣款日是該標的市場的休市日（週末或國定假日），依計畫設定調整：
   - **順延**（預設）：調到下一個交易日
   - 提前：調到前一個交易日
3. 交易日曆：台股用 TWSE 開休市日期表（來源待查，見 07）；美股、日股用後端維護的休市表；基金依台灣營業日。如果日曆資料缺漏，只把週末視為休市，並標示「交易日曆未更新」。
4. 調整後如果和下一期撞在同一天，兩期合併成一筆「待確認」，備註「含 2 期」，但仍保留兩個期別編號，讓使用者自行拆分或合併。
5. 跨月順延（例如 31 日順延到下月 1 日）：仍算原月份那一期，期別編號照原月份。

### 3.3 待確認紀錄與漏記處理

- App 開啟時（以及每天第一次回到前景時），從 `last_generated_date + 1` 到今天，補產生所有到期的期數，狀態為「待確認」。
- 待確認紀錄預先帶入：計畫金額、預估價格（當日或最近一次收盤）、預估數量，並標示為「估計」。
- 使用者可以：
  - **確認**：補上實際成交價、數量、手續費，變成正式紀錄
  - **略過**：該期沒有扣款（例如扣款失敗）
  - **延後**：保留在待確認清單
- 待確認紀錄**不計入**資產與損益。首頁卡片會顯示「有 n 筆待確認，合計約 X 元」。
- 計畫的開始日如果早於今天（例如補建舊計畫），補產生期數前會詢問：「要補產生 YYYY/MM/DD 之後的 n 期待確認紀錄嗎？」使用者也可以選擇不補。
- 每個計畫、每個期別只會產生一筆（唯一鍵 `plan_id + period_key`），重複開啟 App 不會重複產生。
- 時區：台股、基金用 Asia/Taipei；美股用 America/New_York；日股用 Asia/Tokyo。名義日期以該市場時區判斷。

### 3.4 範例

| 計畫 | 名義日期 | 結果 |
|---|---|---|
| 每月 31 日，台股 | 2027-02-31 → 2027-02-28（週日，和平紀念日） | 順延到下一個交易日；若 2027-03-01 為補假，再順延至 2027-03-02（依當年度休市表），期別仍為 2027-02 |
| 每月 6 日，台股 | 2027-03-06（週六） | 順延至 2027-03-08（週一） |
| 每月 29 日 | 2028-02-29（存在，閏年） | 照常 |
| 每週一，美股 | 遇美國休市 | 順延至週二 |
| App 30 天沒開 | | 開啟後一次補產生 4～5 筆待確認 |
