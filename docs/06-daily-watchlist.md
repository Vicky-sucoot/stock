# 06 每日觀察名單：資料流程、評分規則、排序與範例

> **定位**：依公開資料機械式篩選出的「觀察」清單，不構成投資建議，不保證準確或獲利，不提供目標價或價格預測，不自動交易，不推播。
> **範圍**：台股與台灣 ETF（上市與上櫃）放在同一份名單。**MVP（R2-1）**：方向判斷只涵蓋上櫃標的（TPEx 外資資料）；上市標的在取得 TWSE 官方管道與授權前，只會出現在「資料不足」區塊。
> **規則版本**：`rule_version = 2026.11-draft1`。所有門檻都是參數，上線前需要用歷史資料回測後再定案。

## 1. 資料流程（後端排程，台灣時間，只在台股交易日執行）

```
14:30 起  [1] 交易日檢查（trading_calendar；非交易日直接結束，App 顯示上一份名單）
          [2] 抓取收盤行情：TWSE STOCK_DAY_ALL、TPEx tpex_mainboard_quotes（用來算成交量與估計金額）
15:30 起  [3] 抓取外資及陸資買賣超
              - 上櫃：TPEx OpenAPI /tpex_3insti_daily_trading（已查核）
              - 上市：⚠ 來源待查（TWSE OpenAPI 沒有個股三大法人日報，見 07）
          [4] 抓取公司重大訊息：TWSE /opendata/t187ap04_L、TPEx /mopsfin_t187ap04_O（已查核）
          [5] 授權新聞（取得授權後才啟用）：透過合約 API 取得標題、摘要、連結與發布時間
          [6] 驗證資料日：所有外資資料的 Date 必須等於今天的交易日，否則視為「未更新」，稍後重試
          [7] 正規化、去重複、對應代號 → 寫入 foreign_flow_daily / announcement / news_item
          [8] 訊息判定（規則與 LLM）→ signal_assessment
          [9] 評分 → watchlist_run / watchlist_entry
          [10] 發布：App 透過 GET /v1/watchlist/latest 取得（有 ETag 快取）
```

### 重試與完整度

| 步驟 | 重試策略 | 最終失敗時 |
|---|---|---|
| 外資資料 | 15:30、16:00、16:30、17:30、19:00、21:00 各試一次（指數退避，每次單一請求，間隔至少 10 秒，避免對官方造成負擔）；若回傳資料日不是今天，也算未更新 | 該市場標記 `coverage.foreign_TWSE = false`；**該市場的標的不產生方向性結論** |
| 重大訊息與新聞 | 每 30 分鐘一次，到 21:00 為止 | 名單照常產生，但訊息分數全部為 0，並標示「訊息資料缺漏」 |
| 整體 | 21:00 為最後一次產生；之後若有補資料，可手動重跑，產生新 run_id，App 顯示「已於 HH:mm 更新」 | run.status = PARTIAL／FAILED，App 頂部明確顯示 |

> 官方資料的實際公布時間**尚未從官方頁面查核**（TWSE 網站拒絕自動存取）。上面的排程是保守設計，上線前必須確認，見 07。

### 來源追蹤
每一筆 `watchlist_entry.evidence` 都包含：
- 外資原始列：`source_endpoint`、`source_url`、`trade_date`、`fetched_at`、原始欄位值（`raw_json` 的雜湊值，可回溯到後端保存的原始回應）
- 訊息：`item_id`、標題、來源名稱、`published_at`、`url`、判定結果、`rationale`、`model` 與 `prompt_version`
- 計算步驟：每個子分數的輸入值、門檻、得分

## 2. 外資評分 F（範圍 −50～+50）

使用欄位：**外資及陸資（不含外資自營商）買賣超股數**，記為 `net`。另外保存「外資自營商」與「合計」作為原始資料，但不計分，以免重複計算。

衍生值（d 為資料日）：
- `amt = net × close`：估計金額。這是近似值，畫面會明確標示「以收盤價估算」
- `ratio = |net| / volume`：占當日成交量比例
- `streak`：連續同方向（買超或賣超）的交易日數，最多計算到 10 天；`net = 0` 時中斷

| 子分數 | 條件 | 分數（同方向取正，賣超取負） |
|---|---|---|
| 連續性 S1 | 連續 ≥3 天 | 3 天 = 10、4 天 = 13、5 天以上 = 15、8 天以上 = 20 |
| 單日大幅 S2 | `ratio ≥ 10%` **且** `|amt| ≥ NT$30,000,000` | 20；若 `ratio ≥ 20%`，再加 5 |
| 規模 S3 | 當日 `|amt|` 在全市場同方向排名的百分位 | 前 1% = 5、前 5% = 3、前 10% = 1 |

`F = sign × min(50, S1 + S2 + S3)`

- **連續買超**：S1 > 0 且方向為買；**單日大幅買超**：S2 > 0 且方向為買；賣超同理
- 流動性過濾：近 20 日平均成交金額低於 NT$10,000,000 的標的不列入，避免小型股被少量買賣放大
- 歷史資料不足：歷史天數少於 streak 需要的天數時，S1 只算可確認的天數，並加註 `HISTORY_INSUFFICIENT`。TPEx OpenAPI 只回傳最新一天，所以**連續性必須靠後端每天累積**；剛上線的前幾天，S1 會受影響

## 3. 訊息評分 N（範圍 −50～+50）

### 3.1 訊息來源（依授權情況）
1. **官方公司重大訊息**（MVP）：政府資料開放授權，可以保存與顯示主旨，並附上原始連結
2. **授權新聞**（取得授權後）：依合約範圍保存標題、摘要與連結
3. **未授權新聞**：**不爬取、不保存全文、不送進 LLM**

### 3.2 單則判定
每則訊息對每個相關代號，產生：
- `polarity`：+1 利多、0 中性、−1 利空
- `confidence`：0～1
- `relevance`：0～1（主體公司 = 1；同產業或被提及 = 0.3～0.6）
- `rationale`：80 字以內，必須引用訊息中的具體事實（例如「主旨：董事會決議發放現金股利每股 3 元」）

判定流程：
1. **規則先行**：重大訊息的「符合條款」與主旨關鍵字對照表，例如：
   - 更正財報、停止交易、重整、跳票、違約、裁罰 → −1
   - 股利、取得重大訂單、庫藏股 → +1
   - 更名、公告股東會、人事異動 → 0
2. **LLM 輔助**：規則判不出來時才送給 LLM。使用固定提示詞版本，要求輸出 JSON（polarity、confidence、relevance、rationale、negation_detected），溫度設為 0
3. **否定語句**：規則層偵測「未、不、否認、澄清、非屬、取消、終止、無」等否定詞與其修飾範圍；LLM 也要回報 `negation_detected`。兩者結論不同時，confidence 乘以 0.5
4. **澄清公告**（例如「澄清媒體報導」）：預設 polarity = 0，除非內容明確有數字上的利多或利空
5. **一致性檢查**：同一則訊息，規則與 LLM 方向相反時，取 0 並標記 `MODEL_RULE_CONFLICT`

### 3.3 時效（舊聞）
- 有效窗口：**前一個交易日 13:30 到當日 13:30**（台灣時間）之間發布的訊息
- 窗口之外：`is_stale = true`，不計分，只在明細頁列為「近期背景」
- 發布時間缺失：不計分

### 3.4 去重複
- 正規化標題（去除空白、標點、全形與半形差異）後算 `content_hash`
- 相同 hash，或標題 3-gram Jaccard 相似度 ≥ 0.8 且同一代號、24 小時內，歸為同一個 `cluster_id`
- 每個 cluster 只計一次分，取最早發布的那一則為代表；其他列為「其他報導」

### 3.5 彙總
`N = 50 × tanh( Σ_cluster (polarity × confidence × relevance) / 2 )`

## 4. 總分、衝突與不確定性

`S = F + N`（範圍 −100～+100）

| 情況 | 判定 | 處理 |
|---|---|---|
| 該市場沒有外資資料（coverage = false） | 資料不足 | 不列入方向名單；只有在有訊息時，才在「資料不足」區塊列出代號 |
| F = 0 且只有 N | 訊息單獨不足以構成觀察 | 不列入方向名單（避免只靠新聞） |
| `sign(F) ≠ sign(N)` 且 `|F| ≥ 15` 且 `|N| ≥ 15` | 訊號衝突 | 列入「訊號衝突」區塊，顯示兩邊的依據，不給方向 |
| 判定 confidence 平均 < 0.5 | 低信心 | 在該列加註 `LOW_CONFIDENCE`；N 乘以 0.5 |
| 標的當日處置、暫停交易或全額交割 | 特殊狀態 | 標註狀態；此項資料來源待查，MVP 先不做 |

### 列入門檻與排序
- 偏多觀察：`F > 0` 且 `S ≥ 25`
- 偏空／避開觀察：`F < 0` 且 `S ≤ −25`
- 排序：依 |S| 由大到小；同分時依 |amt| 由大到小，再依代號排序
- 顯示：預設前 5 檔，展開最多 10 檔；不足 5 檔就只顯示實際數量，不補位，並顯示「今日符合條件 n 檔」

### 簡短理由（模板產生，不由 LLM 自由撰寫）
`外資連續 {streak} 日{買/賣}超，今日{淨買/淨賣} {net_lots} 張（約占成交量 {ratio}%）；{訊息摘要或「無相關重大訊息」}。`

## 6. 品質監控
- 每日紀錄：各來源筆數、對應代號失敗數、LLM 呼叫數與費用、判定分布
- 每週抽樣 20 則訊息由人工複核判定；**正確率 < 80% 時暫停 LLM 判定，退回只用規則**
- 回測（上線前）：用累積資料比較入榜標的後 5 日與 20 日的表現分布。**結果只作為調整門檻的內部參考，不可在 App 中宣稱績效**（見 08，管理規則第 14 條）
